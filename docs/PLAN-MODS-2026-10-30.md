# Our older Switch mods on TF.EX: custom archers, 8 players, TowerBall (plan, 2026-10-30)

The user's goal: the features of our pre-TF.EX Switch mods (`combined-mod`: the SSB roster and portraits, 8 players, TowerBall,
three teams) brought into the TF.EX / FortRise structure, so they play online on PC (with WiderSet), in the browser and on the
Switch. One at a time. Research reports (read-only, 2026-10-30) summarised here; file references are theirs.

## Recommended order
1. **Custom archers** (smallest; no upstream change). 2. **8 players in wide lobbies** (one upstream TF.EX PR + both servers).
3. **TowerBall** (largest; permission, a FortRise 5 port, rollback state, an upstream PR for third-party modes online).
Ask upstream about 2 and 3 early (one conversation with Fcornaire), since both wait on him; the TowerBall authors' permission too.

## 1. Custom archers as FortRise 5 archer mods
- **Already there:** the Switch loads FortRise 5 archer mods from `sd:/xplay/mods/<folder>/` and TF.EX streams skins both ways
  (commits 0d4c3b4e, 935530c5; docs/research-fortrise-mods-on-switch.md §6-7; emulator PASS with AmongUsRedBlue, console unchecked).
- **Source to convert:** not the flattened Switch romfs but the PC pack it came from, "SSB X TF Archer Loader v1.1.5"
  (`additional-characters/smash-roster-mod/build_unit.py:10,32-51`), old Archer Loader format.
- **Target:** per unit a mod folder: `meta.json` (name e.g. `SSB.Villager`, version, no dll) + `Content/Atlas/{atlas,menuAtlas}.{png,xml}`,
  `Content/Atlas/SpriteData/{spriteData,corpseSpriteData}.xml`, `Content/Atlas/GameData/archerData.xml` (`<Archers>` of `<Archer id>`,
  `<AltArcher id Alt=>`, `<SecretArcher id Secret=>`; FortRise ContentModule.cs:79-143, ArcherLoader.cs:42-79). Online, TF.EX plays a
  custom archer as itself when every peer has the same `mod@version`, else a vanilla stand-in with the streamed art (ArcherData.cs).
- **Work:** a converter next to build_unit.py (reuse its atlas compositing, portrait routing, tag dedupe; drop its slot promotion);
  validate in the browser (custom zip) / PC; one Switch smoke run with the mod on both sides and on one side (streaming).
- **Doesn't map:** `<SkinArcher>` (vanilla reskins: Skin Base, Cyan alt portraits) has no FortRise 5 form (an Alt can't target a
  vanilla archer): standalone archers or dropped (the user decides). Custom SFX (Rosalina) and hair work on PC / browser, not yet on
  the Switch (translator / glue work after).
- **Risks:** the SSB art is Nintendo's and the pack third-party: sideloaded only, never hosted (docs/MODS.md policy in the browser
  repo). Streamed bundles: 1024 px per texture, 5 MB per archer. IDs and versions stay stable (they decide matching).

## 2. 8 players, at most 4 devices, in WiderSet (wide) lobbies
- **Already 8-ready in TF.EX v0.28.0:** MAX_SEATS 8 and MAX_LOCAL_PLAYERS 3, input arrays, WiderSet seats in InputService, the roll
  call layout, TF.State's score arrays; GGRS has no player cap (each seat a handle, guests local handles).
- **Hard 4s:** the lobby player-count button (LobbyVersusPlayerCountButton.cs MAX_PLAYERS 4), team fill (MatchmakingService.cs:1605),
  TF.State's spawning (TF.State.Patchs/RoundLogic/RoundLogic.cs: `Vector2[4]`, `j < 4`, `i < 4`; LevelTestRoundLogic.cs:45: seats 4-7
  would never spawn), NetplayRoundLogic.cs:337, MatchVariants.cs:75 `new bool[4]`, LobbyVersusCoinButton.cs:105 (goals for 2-4);
  servers MAX_PLAYERS 4 (Rust constants.rs:8, lobby.rs, quickplay.rs:151; our matchmaker.js).
- **Upstream:** no 8-player work or issue upstream (WiderSet support there is the wide arena with 2-4 archers).
- **Work:** (a) one TF.EX PR: in wide lobbies the cap is MAX_SEATS, the 4-loops become the player count, goals for 5-8 (ask first:
  gated on WiderSet's IsWide?). (b) Both servers: max 8 only for lobbies carrying WiderSet IsWide. (c) Browser: already loads
  WiderSet 0.9.0; test 4 devices x 2. (d) Switch: translate that TF.EX; raise our own 4s (kNpSeats, kMaxPlayers, kLobbySeats,
  kMaxSeats; a bool[6] mask in lobbymatch.cpp); bring eight-player-mod's native pieces (eightplayer.hpp: arrays 6 -> 8, JoyConInput
  6/7, player 7/8 art, ChestChances rows, the results assert) in as a marked Switch block for wide netplay lobbies only (its planned
  0xbce530 hook collides with ours, tfex/MainMenuPatch.cpp:681); one wide 8-seat emulator scenario.
- **Risks:** TF.State save size at 240 Hz with 8 archers (measure on the console); the Switch's widened tables must match the PC's
  (WiderSet's treasure odds); WiderSet's levels can't be redistributed (how Switch players get them).

## 3. TowerBall as a FortRise game mode, online
- **Ours:** the Switch port is native (~3.2k lines C++, ~28 hooks in tf-switch-exlaunch, mode 6's slot posing as Mode 5); the rules
  come from the PC TowerBall 3.1 source (1,544 lines C#). A FortRise TowerBall exists (CoolModder's "TowerBall For FortRise",
  GameBanana 461512, from Suyooo's v3) but for FortRise 4: it doesn't load on FortRise 5, and it's marked not redistributable with no
  license file.
- **FortRise 5 fit:** IVersusGameMode (IsTeamMode true replaces the Mode 5 pose), Registry.Arrows / Towers / Variants, Harmony.
- **TF.EX online needs (upstream):** online matches run only TF.EX's own Netplay mode; the lobby's mode is an int of the three vanilla
  modes. Needed: the mode by registered name (FortRise's mode numbers depend on load order), the lobby button listing netplay-safe
  modes, NetplayVersusMode handing round logic to that mode while TF.EX keeps netplay init and spawning, replays keeping the name.
- **Rollback:** TF.State saves a fixed list of entity types; mods get `RegisterVariantStateEvents` only. TowerBall's handler must
  save and rebuild the ball (custom arrow fields), the carrier, the round logic's fields, the chest and dropped balls. Its PC code needs
  determinism fixes first (`new Random()`, a System.Timers.Timer, static dictionaries).
- **Switch:** FortRise interface dispatch in the translator (IVersusGameMode is bound straight to NetplayVersusMode today,
  overrides.toml:579-592), modes by name, per-mod translation of TowerBall, its content on the SD card; the native port deleted.
- **Order inside:** permission -> FortRise 5 port, offline, deterministic -> TF.State handlers (TF.EX test mode) -> the upstream PR ->
  browser -> Switch translator -> Switch.
