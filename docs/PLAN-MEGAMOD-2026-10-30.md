# combined-mod inside switch-online (plan, 2026-10-30)

The user's focus: the older megamod (`../combined-mod`: SSB roster + portraits, 8 players, TowerBall, three teams) and the TF.EX
port on the console at the same time, everything working; done so that small changes to TF.EX (or elsewhere) later let the two
interact more (online 8 players, online TowerBall). Background research: docs/PLAN-MODS-2026-10-30.md.

## Why one module
Atmosphere loads one `exefs/subsdk9`: combined-mod's native code (~6.4k lines: main.cpp + towerball*.hpp, eightplayer.hpp,
threeteam.hpp generated by three-team-mod/make_threeteam_hpp.py) has to be built into switch-online's module. The romfs layers by
file and doesn't collide: switch-online adds Content/Levels/PCVersus and PCWide; combined-mod's romfs is Levels/6P-Versus (209
spawn-edited levels), Levels/Versus (16 TowerBall tb.oel), the atlases, spriteData, archerData. Same game binary (1.4.1.6: shared
offsets agree, e.g. MatchSettings.get_TeamMode 0xaba740).

## Where they meet (measured: every InstallAtOffset / CodePatcher site in both trees)
eightplayer's 14 in-place instruction patches (array widening, Session counts, the cap table, the "2-8 ARCHERS" byte) touch nothing
switch-online touches. 14 functions are hooked by both (exlaunch chains them: the later install is outermost):

| function | combined-mod | switch-online |
|---|---|---|
| MatchSettings.get_TeamMode 0xaba740 | TowerBall (mode 6 as a team mode), three-team | FortRise's getter (generated) |
| GetPlayerAllegiance 0xabb5c0, GetMaxTeamSize 0xabb5f0, GetPlayerTeamSize 0xabb910 | TowerBall / three-team | FrModes (Mode 11 as Mode 5) |
| RoundLogic.GetRoundLogic 0xb37f50 | TowerBall (mode 6) | FortRise's dispatch (generated) |
| RoundLogic.SpawnPlayersTeams 0xb39070 | three-team | TF.State's patch (generated) |
| PlayerInput.AssignInputs 0xb054b0 | 8p: JoyConInput 6/7 | TF.EX's prefix |
| RollcallElement.ctor 0xb31f10, get_MaxPlayers, CreateRollcall | 8p: slots 7/8 | TF.EX's roll call (generated) |
| PauseMenu.VersusArcherSelect 0xae2880, Quit 0xae2b50 | 8p: reset joins | TF.EX's end-of-match vote |

Hook budget: switch-online uses 269 of 327 trampolines (pools log); combined-mod ~48: fits, little headroom (the pool is ours to raise).

## The rule
- **Offline is the megamod's, online is TF.EX's.** Each combined-mod hook does its own thing only outside a TF.EX lobby (no own lobby,
  not the Netplay mode) and otherwise calls through, so online stays TF.EX's code, byte for byte what it is today. Offline keeps
  combined-mod's behaviour (8 players at the 2-6 lobby, TowerBall in mode 6, three teams in TDM). One predicate, used by every hook.
- **The roster becomes FortRise archer mods**, not romfs edits: the Switch already loads them from sd:/xplay/mods and TF.EX streams
  them, so the roster works offline AND online against the browser, with no hooks (PLAN-MODS step 1). Its romfs archerData /
  atlas edits retire. Hair and custom SFX on the Switch come with it (the roster uses both).
- Combined-mod's code comes in as its own folder in the module with its source of truth moved here; three-team's generated header is
  regenerated into it.

## Distribution (the user, 2026-10-30: TF.EX for the Switch and the mod baseline go out without TowerBall)
Three layers kept apart: (1) the core module (TF.EX's translation + the FortRise loader), (2) data mods, each a FortRise mod folder in
sd:/xplay/mods/<name>/ with its own version (the roster: one per character, never hosted: Nintendo's art), (3) native features
(TowerBall, 8 players, three teams) compiled into the module, each in its own folder behind a build setting. Two builds from one
tree ("TF.EX Switch", "TF.EX Switch + extras"); data mods are separate downloads (TF.EX matches them by name and version).
**The two builds (2026-10-31):** the build setting `XPLAY_EXTRAS` (hw-probe/exlaunch/config.mk, `-DXPLAY_EXTRAS`): 1 (the default) is
"TF.EX Switch + extras", what the console runs (`tools/build-probe.sh` -> deploy/); 0 is "TF.EX Switch" (`XPLAY_EXTRAS=0
tools/build-probe.sh` -> deploy-core/, its own mirror folder and ELF tfx-hw-exlaunch-core.elf): megamod.cpp and localtest.cpp compile to
nothing and megamod.hpp's calls are no-ops (`[megamod] not in this build`), so local play is the game's (6 seats). The boot line names
the build (`hardware probe injected (built ..., TF.EX Switch)`). `XPLAY_EXTRAS=0` in front of the run scripts runs the core build
(run-probe.sh: deploy-core/, and `romfs.py --clean` takes the megamod's game data out of the romfs). Checked: smoke lobby on the core
build in sync (002922). Not set up: a package for other people (where it is downloaded from, and the game data a release can't
carry: the PC levels and the megamod's atlases are made from the game's own files).

## The roster as FortRise 5 archer mods (step 1, 2026-10-30)
`tools/mods/ssb_to_fortrise.py` converts the PC pack (SSB X TF Archer Loader v1.1.5) by build_unit.py's units into 18 mods (SSB.<Hub>)
plus MexicanPuppet (was BeardedPuppet: the reskinned Cyan alt, MEXICAN PUPPET). On the Switch a rule for this archer only (glue
SwitchMods.NativeReskin, tfex/FrModsBoot.cpp; TFEX-DIFF S-native): local play shows it in the game's Prancing Puppet alt slot (its names
and bearded portraits there, its own archer hidden: GetArcherUnlocked false offline); online it is its own archer (TF.EX sends it by name
and streams its art to a PC without the mod), the game's alt is its vanilla self and an archer 6 roll call element can't stay on it
(pcgameplay::Set switches; 2026-10-30, smoke lobby 182946 in sync, the bundle sent; the page drawing it unconfirmed). Output:
`additional-characters/fortrise-mods/<mod>/` (outside git). To put them on the console: FTP each folder to `sd:/xplay/mods/<mod>/`.
Rules it applies: "@" on every reference to the mod's own textures and sprites (FortRise 5 looks only names starting with "@" up in
the mod), Alt / Secret = "<mod>/<hub id>", a hub that is a costume in the pack inherits what it leaves out from its pack parent (and
that art comes into the mod), repeated tags keep the last, <Gender> -> <Genders>, Rosalina's sounds as <SFX>path/{action}</SFX>.
Checked: all 20 mods (with AmongUsRedBlue) load on the Switch (30 archers, `[frmods] done`); the browser's FortRise loads them and
shows a roster archer's portrait. Online (smoke lobby, the Switch on a mod archer, the page with the mod): in sync with a roster
archer (SSB.LastOfTheToadstools, 103754) and with AmongUsRedBlue (103517). The two failures seen first were the harness: the page's
default archer was the stand-in TF.EX gives a not-yet-shared mod archer (upstream candidate 4), and the sync deadline counted the
Switch's 12-17 archer steps.

## Steps
1. **Roster as FortRise mods** (no native code): the converter, the browser check, one Switch run with a roster archer online.
2. **Import combined-mod's code** (done 2026-10-30, above) behind the offline predicate; resolve the 14 shared hooks one by one (chain order and gating);
   the romfs (6P-Versus, TowerBall levels, 8p's player 7/8 art) into switch-online's SD / channel content. Emulator: an offline 8-player
   FFA, TowerBall 4v4, a three-team TDM, and smoke lobby to show online is unchanged.
3. **Hair and custom SFX** for FortRise archers on the Switch (translator / glue).
4. **Unlocks with small upstream changes** (later): 8 seats in WiderSet lobbies (one TF.EX PR + both servers) brings 8 players online;
   modes by registered name brings TowerBall online (bigger: TF.State handlers, the FortRise 5 port).
