- **Switch crash on backing out of a lobby with a browser player** (console, 2026-10-25 08:26; `.devserve/results/20261025-082650-*`).
  Fault at game +0xb33608, `RollcallElement.JoinedUpdate`: the remote seat's roll-call element has a null `input`. On the PC, TF.EX's
  `InputService.EnsureRemoteControllers` gives every remote seat `new KeyboardInput()`. Our overrides.toml made it a no-op ("every seat has
  a JoyConInput"), which stopped being true once the controller fallback went (0af42e5f). In the frame the lobby empties, TF.EX's
  JoinedUpdate prefix lets the game's code run, and that code dereferences null.
  Fix: EnsureRemoteController(s) translated (the TF.EX code itself). TFEX-DIFF S-input: `new KeyboardInput()` becomes
  `svc::NewRemoteSeatInput()`, a JoyConInput over the local JoyCon whose menu getters are muted by IsForeignSeat, as the PC's are. The
  hand copy in lobbymatch.cpp is deleted. Translator: an `IEnumerable<primitive>` parameter is a value list, with the argument copied in
  at the call (only the parameter; `seats.Where(..)` and `IReadOnlyDictionary.Keys` stay lazy).
  Smoke: new scenario `backout` (hw.txt `lobbyback 1`) PASS; `lobby` PASS (0/594).
  **Console check:** back out of a hosted lobby with a browser player in it. Log lines: `[input] TF.EX's EnsureRemoteControllers: a
  remote seat's controller ...`, and no CRASH.
